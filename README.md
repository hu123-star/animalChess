按照“**前端只管照着棋盘数据画，逻辑和规则全由后端仲裁**”的设计，将所有事件广播、失败回复、模式通知全部砍掉，只保留最核心的**状态快照轮询**与**移动提交**。

# 斗兽棋极简通信协议说明

```
┌─────────────────────────────────────────────────────────┐
│                    UE 渲染前端 (纯展示)                   │
│   (只做两件事：1. 轮询拉取 63 格数据照着画；2. 点哪发哪)      │
└────────────────────────────▲────────────────────────────┘
                             │
               [ 协议一：UE ↔ MFC (本地极简 IPC) ]
                 1. 查询当前棋盘快照
                 2. 尝试走子(src -> dst)
                             │
┌────────────────────────────▼────────────────────────────┐
│                    MFC 核心后端 / 大厅                   │
│         (维护唯一权威棋盘，非法走子直接忽略不改数据)          │
└────────────────────────────▲────────────────────────────┘
                             │
               [ 协议二：双机联机对战 (MFC ↔ MFC) ]
                 1. 握手与阵营分配
                 2. 走子同步 (src -> dst)
                             │
┌────────────────────────────▼────────────────────────────┐
│                    远端 MFC 对战节点                     │
└─────────────────────────────────────────────────────────┘
```

---

## 一、基础编码与坐标定义

### 1. 棋盘坐标映射
* 棋盘为 $7$ 行 $\times 9$ 列，共 $63$ 个有效格子（`0 ~ 62`）。
* **换算公式**：`Index = Row * 9 + Col`（Row: 0～6, Col: 0～8）。

### 2. 棋子编码（1 Byte）
* `0`：空格（无棋子）
* `1 ~ 8`：**红方**（象1、狮2、虎3、豹4、狼5、狗6、猫7、鼠8）
* `17 ~ 24`：**蓝方**（象17、狮18、虎19、豹20、狼21、狗22、猫23、鼠24）

---

## 二、协议一：UE 前端 ↔ MFC 后端（本地通信）

传输方式：本地 TCP Socket（`127.0.0.1:9001`）或具名管道。

### 统一数据包格式
```
┌──────────────┬──────────────┬──────────────┬────────────────────────┐
│ Magic (2B)   │ MsgID (2B)   │ Length (4B)  │ Body (Length Bytes)    │
│ 0x55, 0xAA   │ 消息ID       │ 包体字节数   │ 结构体数据             │
└──────────────┴──────────────┴──────────────┴────────────────────────┘
```

### 1. 轮询拉取全量棋盘状态
* **请求**：`REQ_GET_BOARD`（MsgID = `0x0001`，包体为空）
* **响应**：`RSP_GET_BOARD`（MsgID = `0x0002`）

```c
struct MsgBoardSnapshot {
    uint8_t gameStatus;   //0:进行中, 1:红胜, 2:蓝胜, 3:和棋
    uint8_t currentTurn;  //0:轮到红方, 1:轮到蓝方
    uint8_t lastSrc;      //上一步起点(0~62, 255表示无)
    uint8_t lastDst;      //上一步终点(0~62, 255表示无)
    uint8_t board[63];    //63个格子的全量棋子数据
};
```

> **UE 渲染逻辑**：
> UE 定时（如每秒 20 次）向 MFC 发送 `REQ_GET_BOARD`。UE 收到 `board[63]` 后：
> * 遍历 63 个格子，对应位置该显示什么子就显示什么子。
> * 比对上一帧数据，如果发现某个格子棋子位置变了，自动播放位移或吃子消失，完全不需要额外事件通知。

---

### 2. 提交移动请求
* **请求**：`REQ_MOVE_PIECE`（MsgID = `0x0003`）
* **响应**：无（不需要返回失败原因）。

```c
struct MsgMovePiece {
    uint8_t srcIndex;     //玩家点击的起点格 (0 ~ 62)
    uint8_t dstIndex;     //玩家点击的终点格 (0 ~ 62)
};
```

> **MFC 处理逻辑**：
> * 收到后进行规则判定。如果**合法**，MFC 内部更新 `board[63]`；如果**非法**，MFC 直接忽略，不修改数据。
> * UE 在下一次轮询时拿到新数据就自然更新；拿到的还是老数据就保持原样。

---

## 三、协议二：双机联机对战通信（MFC ↔ MFC）

双机直连时，房主端（Host）作为规则权威裁决端，客机（Guest）只同步操作。

* 默认监听端口：`9002`（可在界面修改）。
* Host 固定为红方并先手，Guest 固定为蓝方并后手。
* `MsgID` 和 `Length` 均使用网络字节序（大端）；TCP 接收端按 `Length` 处理拆包和粘包。
* 当前版本支持一局一连接，断线后不续局，重新创建或加入房间会重置棋局。
* Host 会忽略无效的握手连接并继续等待；已进入对局后若 Guest 提交非法或不同步走子，则主动断开以防止双方局面分叉。

### 1. 握手与连接
* **请求**：`NET_JOIN_REQ`（MsgID = `0x0010`，Guest $\rightarrow$ Host）
* **响应**：`NET_JOIN_ACK`（MsgID = `0x0011`，Host $\rightarrow$ Guest）

```c
struct NetJoinAck {
    uint8_t accept;       //1:同意加入, 0:拒绝
    uint8_t assignedCamp; //分配阵营 (0:红方/先手, 1:蓝方/后手)
};
```

---

### 2. 同步走子操作
* **消息**：`NET_MOVE_SYNC`（MsgID = `0x0012`，双向）

```c
struct NetMoveSync {
    uint8_t srcIndex;     //起点 (0 ~ 62)
    uint8_t dstIndex;     //终点 (0 ~ 62)
};
```

> **联机走子流程**：
> 1. 客机玩家走子：Guest_UE $\rightarrow$ Guest_MFC $\rightarrow$ 发送 `NET_MOVE_SYNC` 给 Host_MFC。
> 2. Host_MFC 校验该走子合法后，更新主机棋盘，并给 Guest_MFC 回传确认的 `NET_MOVE_SYNC`。
> 3. 双方 MFC 内部棋盘各自更新，两端的 UE 在下一次轮询时自动画出最新棋盘。

### 3. 局域网对战使用方法

> 构建环境：Windows + Visual Studio，并安装 `v141` C++ 工具集、MFC（x86/x64）和 Windows 10 SDK。

1. 两台 Windows 电脑连入同一局域网（同一 Wi-Fi 或网线网络）并启动程序。
2. 房主保留或修改端口，点击“创建房间（红）”，然后把界面显示的局域网 IP 和端口告诉另一方。
3. 加入方填入房主 IP 和相同端口，点击“加入房间（蓝）”。
4. 两边都显示“已连接”后即可开始；程序会自动限制只能在本方回合操作本方棋子。

> Windows 首次监听端口时可能弹出防火墙提示，需允许程序访问“专用网络”。若要在同一台电脑测试，加入方可填写 `127.0.0.1`。联机包未加密，请仅在可信局域网中使用。

## 四、完整的交互时序

```
UE 前端                               MFC 后端 (人机/联机)
  │                                           │
  │─── 1. REQ_GET_BOARD (轮询) ──────────────>│
  │<── 2. RSP_GET_BOARD (board[63]) ──────────┤ (UE 照着 63 字节数组画出初始棋盘)
  │                                           │
  │─── 3. REQ_MOVE_PIECE (从 10 走到 11) ────>│ (MFC 校验合法，修改内部棋盘数据)
  │                                           │ (若是非法移动，MFC 直接忽略不改数据)
  │                                           │
  │─── 4. REQ_GET_BOARD (轮询) ──────────────>│
  │<── 5. RSP_GET_BOARD (新的 board[63]) ─────┤ (UE 发现数据变化，直接刷新渲染)
  │                                           │
```

### 核心分层设计
* **后端引擎层 (`engine.h` / `engine.cpp`)**：
  维护权威棋盘数据，实现走子规则判定、吃子与跳河约束、局面胜负裁决以及 Alpha-Beta 博弈搜索。对外部完全解耦，不依赖任何 MFC 界面库函数。
* **局域网会话层 (`LanNetwork.h` / `LanNetwork.cpp`)**：
  在后台线程完成房主监听、客机连接、握手与完整包收发，再通过带会话编号的 Windows 消息把走子交回界面线程，避免旧连接消息污染新棋局。
* **前端展示层 (`animalChessDlg.h` / `animalChessDlg.cpp`)**：
  作为“纯表现层”客户端。不参与任何规则计算，仅通过 `Engine_GetSnapshot` 获取 63 字节的棋盘全量快照进行渲染，并将玩家的落子请求（起点和终点索引）通过 `Engine_TryMove` 提交给后端。**后续接入 Unreal Engine 时，只需将该文件内的渲染逻辑用 UE 的 Actor / Widget 替换即可。**

## 二、核心数据结构与协议定义

### 1. 全量棋盘快照 (`MsgBoardSnapshot`)
用于前端拉取并在屏幕上绘制棋局的单一数据源。

```cpp
#pragma pack(push, 1)
struct MsgBoardSnapshot {
    uint8_t gameStatus;                // 对局状态：0=进行中, 1=红方胜, 2=蓝方胜, 3=和棋
    uint8_t currentTurn;               // 当前轮次：0=红方(玩家), 1=蓝方(AI/远端)
    uint8_t lastSrc;                   // 上一步起点索引 (0~62, 255表示无)
    uint8_t lastDst;                   // 上一步终点索引 (0~62, 255表示无)
    uint8_t board[BOARD_CELL_COUNT];   // 63个格子的全量棋子数据
};
#pragma pack(pop)
```

### 2. 棋盘格子索引映射
* 棋盘规格为 **7 行 $\times$ 9 列**，共 63 个格子。
* **索引计算**：`Index = Row * 9 + Col`（`Row` 范围 `0 ~ 6`，`Col` 范围 `0 ~ 8`）。

### 3. 棋子与地形数值映射
* **棋子编码 (`uint8_t`)**：
  * `0`：无棋子
  * `1 ~ 8`（红方）：象(1)、狮(2)、虎(3)、豹(4)、狼(5)、狗(6)、猫(7)、鼠(8)
  * `17 ~ 24`（蓝方）：象(17)、狮(18)、虎(19)、豹(20)、狼(21)、狗(22)、猫(23)、鼠(24)
* **地形编码 (`TerrainType`)**：
  * `0`：陆地
  * `1`：红方兽穴（坐标 Row=3, Col=0）
  * `2`：红方陷阱
  * `3`：河流水域
  * `4`：蓝方陷阱
  * `5`：蓝方兽穴（坐标 Row=3, Col=8）

---

## 三、对外导出接口说明

所有接口均声明在 `engine.h` 中，提供给前端渲染层（MFC 或 UE）以及网络同步模块调用。

### 1. `void Engine_Startup()`
* **功能**：初始化或重置对局。
* **说明**：重置双方 16 颗棋子到初始站位，清空历史走法记录，将先手方设为红方，重置对局状态为进行中。

---

### 2. `void Engine_GetSnapshot(MsgBoardSnapshot& outSnapshot)`
* **功能**：获取当前权威棋盘的完整状态快照。
* **参数**：
  * `outSnapshot` [输出]：接收打包好的快照结构体。
* **说明**：前端（UE 或 MFC）每次刷新界面前调用该函数，直接根据快照中的 `board[63]` 数组渲染棋子。

---

### 3. `bool Engine_IsLegalMove(uint8_t srcIdx, uint8_t dstIdx)`
* **功能**：无副作用地检查一步走子是否合法。
* **说明**：不会修改棋盘、回合或历史记录；联机 Guest 在向 Host 提交请求前使用此接口预检。

---

### 4. `bool Engine_TryMove(uint8_t srcIdx, uint8_t dstIdx)`
* **功能**：提交走子请求。
* **参数**：
  * `srcIdx` [输入]：移动起点格子索引（`0 ~ 62`）。
  * `dstIdx` [输入]：移动目标格子索引（`0 ~ 62`）。
* **返回值**：
  * `true`：移动合法，后端已更新棋盘并切换回合。
  * `false`：移动非法（违规跳河、等阶不足、进己方兽穴等），后端忽略该操作，棋盘状态不变。

---

### 5. `bool Engine_TriggerAi()`
* **功能**：触发本地 AI 计算并执行一步棋。
* **返回值**：
  * `true`：AI 成功完成走子并更新棋盘。
  * `false`：当前并非 AI 回合或对局已结束。
* **说明**：在玩家成功执行 `Engine_TryMove` 后调用，AI 思考完成后会直接修改内部棋盘并更新 `lastSrc` 和 `lastDst`。

---

### 6. `TerrainType Engine_GetTerrainByIndex(uint8_t idx)`
* **功能**：查询指定格子的地形类型。
* **参数**：
  * `idx` [输入]：格子索引（`0 ~ 62`）。
* **返回值**：返回该格子的 `TerrainType`（河流、陷阱、兽穴或普通陆地）。

---

### 7. `const char* Engine_GetPieceName(uint8_t pc)`
* **功能**：获取棋子对应的中文字符串。
* **参数**：
  * `pc` [输入]：棋子数值（`0 ~ 24`）。
* **返回值**：返回 `"象"`、`"狮"` 等 UTF-8 文本（无棋子返回全角空格 `"　"`）。

---

## 四、未来无缝替换为 UE 前端的对接规范

当切换为 Unreal Engine 实现 3D 前端时，交互逻辑保持完全一致：

1. **渲染阶段**：
   * UE 创建 63 个网格 Actor；
   * 每帧（或定时）调用 `Engine_GetSnapshot(snap)`，比对 `snap.board[i]`；
   * 若发现某格子产生位移，UE 播放平移/跳跃动画；若被吃子，播放销毁特效。
2. **输入阶段**：
   * 玩家点击棋子与目标格后，UE 直接调用 `Engine_TryMove(srcIdx, dstIdx)`；
   * 若返回 `true`，接着调用 `Engine_TriggerAi()`；
   * 下一帧 UE 再次读取 `Engine_GetSnapshot`，画面即可自动刷新出 AI 的走子。
